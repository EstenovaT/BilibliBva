  DNS only（仅 DNS、关闭代理）直连服务器部署方案
  —— 不需要 Cloudflare 代理，域名直接用 A 记录指向服务器
════════════════════════════════════════════════════════════

一、适用场景
────────────────────────────────────────────────────────────
  - 不想用 Cloudflare 代理（橙云），只要 Cloudflare 当 DNS
  - 服务器直接对外提供服务（Nginx + HTTPS）
  - 服务器必须是【国内 IP】（否则调 B 站 API 仍会被 -412 风控）
  ⚠️ 国内云服务器用未备案域名对外提供 Web 服务存在合规风险，
     请自行评估（阿里云/腾讯云会对未备案域名拦截 80/443）

二、架构
────────────────────────────────────────────────────────────
  用户浏览器 → https://bva.estenova.top（A 记录，灰云 DNS only）
             → 国内服务器 Nginx(443, certbot HTTPS)
             → 127.0.0.1:8080（Python 后端）
             → B 站 API（国内 IP 出站，无风控）

三、DNS 设置（Cloudflare 控制台）
────────────────────────────────────────────────────────────
  1. 若域名此前绑过 Worker：先解除绑定
       Workers & Pages → bva-resolve → Settings → Domains → Remove
  2. DNS → Add record：
       Type: A
       Name: @（或 bva）
       IPv4: 服务器公网 IP
       Proxy status: 【关闭】（灰云/DNS only）← 关键
  3. 等待生效（可用 nslookup bva.estenova.top 确认直连到服务器 IP）

四、服务器配置（国内 Linux 服务器）
────────────────────────────────────────────────────────────
  1. 开放端口：安全组/防火墙放行 80、443
  2. 安装依赖：
       sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
  3. 部署项目（已含全部代码）：
       sudo mkdir -p /opt && cd /opt
       sudo git clone https://github.com/EstenovaT/BilibliBva.git
       # 或上传仓库 ZIP 解压到 /opt/biliblivBva
  4. 启动 Python 后端（systemd，仓库已带单元文件）：
       sudo cp /opt/biliblivBva/deploy/tunnel/bili-resolve.service /etc/systemd/system/
       sudo systemctl daemon-reload
       sudo systemctl enable --now bili-resolve
       curl http://127.0.0.1:8080/        # 验证后端
  5. 配置 Nginx：
       sudo cp /opt/biliblivBva/deploy/nginx/bva.estenova.top.conf /etc/nginx/sites-available/
       sudo ln -s /etc/nginx/sites-available/bva.estenova.top /etc/nginx/sites-enabled/
       sudo nginx -t && sudo systemctl reload nginx
  6. 申请 HTTPS 证书（certbot 自动配好跳转）：
       sudo certbot --nginx -d bva.estenova.top
       按提示填邮箱、同意条款即可
  7. 验证：
       浏览器访问 https://bva.estenova.top/ ，输入 BV 号解析

五、与 Tunnel 方案的对比
────────────────────────────────────────────────────────────
  DNS only 直连          vs    Cloudflare Tunnel
  ├─ 需公网 IP + 开放端口        ├─ 无需公网 IP/端口（出站连接）
  ├─ HTTPS 服务器自签(certbot)   ├─ HTTPS 由 Cloudflare 边缘提供
  ├─ 国内服务器需备案            ├─ 域名仍走 Cloudflare（橙云必须开）
  └─ Nginx 反代                  └─ cloudflared 转发
  说明：Tunnel 方案【必须】开代理（橙云），与"只要 DNS"互斥；
  两者都要求后端在国内 IP 出站才不被 B 站风控。

六、常见问题
────────────────────────────────────────────────────────────
  Q: 关掉代理后网站打不开？
  A: 确认 A 记录已生效（nslookup 显示服务器 IP）；服务器 80/443
     端口已放行；Nginx 已启动（systemctl status nginx）
  Q: certbot 申请失败？
  A: 确认域名已解析到本服务器且 80 端口可达
     （certbot 需要 HTTP-01 验证）
  Q: 必须用国内服务器吗？
  A: 是。海外服务器 IP 调 B 站 API 同样会被 -412 风控，
     那就回到了 Worker 方案的同样问题
